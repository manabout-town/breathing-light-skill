# breathing-light — 호흡 인트로 + 창가 빛 히어로

align-pilates.vercel.app(2026-09-17)에서 만들고 유저가 "좋다"고 확정한 연출을 재사용 가능하게 묶은 것.
두 조각은 따로도, 같이도 쓸 수 있다. 같이 쓰면 **어두운 방 → 호흡 → 원이 창처럼 열림 → 창가 햇살이 든 방**으로
한 장면처럼 이어지는 게 핵심이다.

## 이 스킬을 고를 때
조작 없이 **분위기(빛·호흡)** 가 주인공일 때. 유저 기준으로 인트로/히어로는 "선보다 배경, 가능하면 핵심 품목을 조작"이 우선이므로
상품이 분명한 쇼핑몰·브랜드 사이트는 먼저 **signature-hero**를 검토하고, 이 스킬은 배경 빛 레이어(overlay 모드)로 곁들인다.
인트로 모양은 `shape`(circle·key·square)로 브랜드에 맞춘다.

## 파일

| 파일 | 역할 |
|---|---|
| `assets/breathing-light.css` | 인트로 스타일 + 히어로 캔버스 자리. 색·길이는 `--bl-*` 변수만 수정 |
| `assets/breathing-intro.js` | `BreathingIntro.start({duration,onOpen})` — 시간 뒤 열기, 스크롤·탭·키로 건너뛰기 |
| `assets/window-light.js` | `WindowLight.mount(canvas,{preset,...})` — WebGL 창가 빛 배경 |
| `assets/demo.html` | 둘을 붙인 최소 예제 (`?preset=dusk` 등으로 비교) |
| `scripts/verify.mjs` | 인트로 시점별 컷 + 폰 폭 히어로 검사 (playwright) |
| `references/pitfalls.md` | 실제로 밟은 함정 6개 — **붙이기 전에 읽기** |
| `references/tuning.md` | 업종별 프리셋·변수 조합, 세기 조절 기준 |

## 작업 순서

1. **스타일 먼저 확인.** 이 연출은 차분한 업종용이다. 브루탈리즘·Y2K·게임처럼 에너지가 큰 사이트엔 맞지 않으니
   그럴 땐 다른 연출을 권한다. 프리셋은 `references/tuning.md`에서 사이트 배경색에 가장 가까운 것을 고른다.
2. **파일 복사.** 세 개의 asset을 프로젝트에 넣는다(단일 HTML 사이트면 `<style>`/`<script>`에 인라인해도 됨).
3. **마크업.** `demo.html`의 `#bl-intro` 블록을 `<body>` 맨 앞에, `<canvas id="bl-bg">`를 히어로 섹션의 첫 자식으로
   넣고 히어로에 `bl-hero` 클래스를 붙인다. 히어로가 `max-width` 컨테이너여도 캔버스는 100vw로 화면 전체를 덮는다.
4. **연결.** `WindowLight.mount(...)` 후 `BreathingIntro.start({duration, onOpen})`.
   사이트에 이미 "준비 완료" 클래스(예: `body.ready`)로 제목이 올라오는 연출이 있으면 `onOpen`에서 그 클래스를 붙인다 —
   원이 열리는 순간 제목이 올라와야 한 장면처럼 보인다.
5. **기존 로더가 있으면 교체.** 로더를 두 개 겹치지 말 것. 기존 로더의 타이머·건너뛰기 코드를 지우고 이 스킬 것으로 바꾼다.
6. **색 맞추기.** `--bl-arc`는 사이트 포인트 컬러(조금 밝게), `--bl-hero-fallback`은 사이트 배경색 그라디언트로.
   인트로 방 색(`--bl-room-*`)은 어둡게 유지해야 "창이 열리는" 대비가 산다.
7. **눈으로 검증.** 아래 "검증" 필수. 이 연출의 실패 1순위는 "붙였는데 안 보임"이다.

## 검증 (완료 보고 전 필수)

- `node scripts/verify.mjs <로컬URL> <출력폴더>` → 모든 폭이 `OK`인지, 인트로 컷 3장·히어로 컷을 **직접 열어 본다**.
- **켠/끈 비교:** 실제 브라우저에서 `document.getElementById('bl-bg').style.visibility='hidden'` 전후 스크린샷을 비교한다.
  차이가 한눈에 안 보이면 약한 것이다 → `strength`·`leaf`를 올리거나 프리셋 `shade`를 더 어둡게.
  (align-pilates 1차 배포는 이 비교를 안 해서 "바뀐 게 없다"는 피드백을 받았다.)
- 글씨 가독성이 효과보다 우선. 빛줄기가 본문 글씨 대비를 해치면 `strength`를 낮추거나 `angle`로 빛을 글씨 반대편으로 돌린다.
- 인트로 대기 중 가운데가 비치지 않는지(흰 원이 보이면 mask 순서 오류, pitfalls 2번).
- 배포까지 했다면 라이브 URL을 curl로 받아 새 코드가 들어갔는지 확인.

## 조절 요약

- 인트로 길이: CSS `--bl-dur`와 JS `duration`을 같이 바꾼다(2.4~4초 권장, 그 이상은 이탈).
- 배경 세기: `strength`(빛) · `leaf`(잎 그림자) · 프리셋 `shade`(바탕 어둡기). 한 번에 하나씩.
- 움직임: `period`(호흡 주기, 기본 8초) · `sway`(커튼 속도).
- 배터리: `scale` 기본 .5 — 부드러운 그림이라 더 낮춰도(.35) 티가 거의 안 난다.
- 접근성: reduced-motion이면 인트로는 생략, 배경은 정지 프레임 1장.
